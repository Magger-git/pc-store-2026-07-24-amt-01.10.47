# NODE.PC — интернет-магазин компьютеров и комплектующих

Полноценный магазин на Node.js/Express: каталог, конструктор сборки ПК с
проверкой совместимости, корзина и оформление заказа с оплатой (Stripe).

## Возможности

- **Каталог** с фильтрацией по категориям (процессоры, платы, память, видеокарты, накопители, БП, корпуса).
- **Конструктор сборки** — выбор компонентов с автоматической проверкой совместимости:
  - сокет процессора и материнской платы;
  - тип памяти (DDR4/DDR5) и число слотов;
  - форм-фактор платы и корпуса;
  - длина видеокарты и максимально допустимая в корпусе;
  - расчётная мощность и запас блока питания.
- **Корзина** — привязана к сессии пользователя (cookie), хранится на сервере.
- **Оформление заказа** — форма с контактными данными и адресом.
- **Оплата** — интеграция со Stripe Checkout. Без ключей Stripe работает
  mock-режим (заказ сразу подтверждается) — удобно для разработки и демо.

## Стек

- Backend: Node.js + Express, база данных PostgreSQL.
- Frontend: чистый HTML/CSS/JS без сборщиков — просто статические файлы.
- Оплата: Stripe Checkout (опционально).

## Установка и запуск (локально)

Требуется Node.js версии 18+ и доступ к PostgreSQL (локальный сервер или
бесплатная облачная база, например на Render — см. ниже, можно использовать
её и для локальной разработки).

```bash
cd pc-store
npm install
cp .env.example .env
```

Открой `.env` и впиши строку подключения к базе в `DATABASE_URL`. Дальше:

```bash
npm start
```

При первом запуске сервер сам создаст нужные таблицы и загрузит товары из
`server/data/products.json` в базу. Сайт будет доступен на
`http://localhost:3000`.

Для разработки с автоперезапуском при изменении файлов:

```bash
npm run dev
```

## Деплой в интернет (Render, бесплатно)

1. **Залей проект на GitHub.** Зарегистрируйся на [github.com](https://github.com),
   создай репозиторий и загрузи туда содержимое папки `pc-store` (кнопка
   «Add file → Upload files» на странице репозитория подходит для этого).

2. **Создай базу данных.** На [render.com](https://render.com) → New →
   PostgreSQL → выбери бесплатный тариф (Free). После создания зайди в
   Dashboard базы → Connect → скопируй **Internal Database URL** (если сайт
   тоже будет на Render) или **External Database URL** (если подключаешься
   откуда-то ещё, включая локальный компьютер).

3. **Создай веб-сервис.** New → Web Service → выбери свой репозиторий:
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
   - **Environment:** Node
   - В разделе **Environment Variables** добавь `DATABASE_URL` со значением
     из шага 2 (Internal URL). При желании подключить реальную оплату —
     добавь и `STRIPE_SECRET_KEY`.

4. Нажми **Deploy**. Через пару минут сайт будет доступен по адресу вида
   `https://твой-сайт.onrender.com` — уже не только на твоём компьютере, а
   в интернете, и будет работать даже если твой компьютер выключен.

   На бесплатном тарифе Render "усыпляет" сервис после ~15 минут без
   запросов и снова "будит" его при следующем заходе (первая загрузка после
   паузы может занять 30–60 секунд) — это ограничение бесплатного плана, не
   ошибка проекта.

## Подключение реальной оплаты (Stripe)

1. Зарегистрируйтесь на [stripe.com](https://stripe.com) и возьмите тестовый
   секретный ключ в [дашборде](https://dashboard.stripe.com/test/apikeys)
   (начинается с `sk_test_...`).
2. Впишите его в `.env` (локально) или в Environment Variables на Render
   (в проде):
   ```
   STRIPE_SECRET_KEY=sk_test_...
   ```
3. Перезапустите сервер. Теперь при оформлении заказа пользователь будет
   перенаправлен на настоящую страницу оплаты Stripe Checkout.
4. Для боевого режима замените ключ на `sk_live_...` и настройте вебхук
   `checkout.session.completed`, если нужно надёжно подтверждать оплату
   на сервере (в этой заготовке заказ создаётся сразу при создании сессии
   оплаты — для продакшена рекомендуется подтверждать заказ по вебхуку).

## Панель администратора

По адресу `/admin.html` (например `https://ваш-сайт.onrender.com/admin.html`)
доступна панель управления:

- добавление, редактирование и удаление товаров без прямого доступа к базе;
- просмотр всех оформленных заказов.

**Вход:** пароль задаётся переменной окружения `ADMIN_PASSWORD` (см.
`.env.example`). Обязательно смените пароль по умолчанию перед тем, как
показывать сайт кому-либо — на Render это делается в разделе **Environment**
вашего веб-сервиса, так же как `DATABASE_URL`.

Это простая защита паролем без ролей и множества пользователей — подходит
для одного владельца магазина. Для более серьёзной защиты в будущем стоит
добавить полноценную аутентификацию.

## Как добавить/изменить товары

Проще всего — через панель администратора (`/admin.html`), см. выше.

Альтернативный способ — напрямую через базу данных. Товары хранятся в
таблице `products`. Она заполняется один раз — при первом запуске сервера —
из файла `server/data/products.json`.
Есть два способа что-то добавить:

- **До первого запуска (или с чистой базой):** отредактируйте
  `server/data/products.json` (скопируйте похожий товар и поменяйте поля —
  см. подсказки ниже) и запустите сервер — новые записи попадут в базу.
- **Когда сервер уже работал и товары в базе есть:** правки в JSON-файле
  больше не подхватятся автоматически (сработает только сид "в пустую
  таблицу"). Проще всего добавить товар напрямую SQL-запросом к базе,
  например через `psql` или графический клиент (pgAdmin, TablePlus,
  расширение PostgreSQL в VS Code), либо временно очистить таблицу
  `products` и перезапустить сервер, чтобы сид прошёл заново.

Каждый товар обязан содержать `category` (`cpu`, `motherboard`, `ram`,
`gpu`, `storage`, `psu`, `case`) и блок `specs`, который использует
конструктор для проверки совместимости. Ориентируйтесь на уже существующие
записи той же категории — набор полей `specs` для каждой категории
фиксирован (см. `server/compatibility.js`).

## Известные ограничения демо-версии

- Нет админ-панели для управления товарами (пока только через сид-файл или прямые SQL-запросы — см. раздел выше).
- Нет аутентификации пользователей — заказы не привязаны к личному кабинету.
- Идентификация сессии — простой cookie без шифрования содержимого сессии.
- Оплата по Stripe подтверждает заказ сразу при создании сессии, а не по вебхуку — для продакшена это стоит доработать (см. раздел про Stripe выше).
